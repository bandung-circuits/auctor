# Group 10 Orchestrator — Expert-Driven Deep Analysis & Writing

## Your Role

You are the coordinator of Group 10 in the Auctor news commentary production system. You orchestrate the deep analysis pipeline that begins after expert interviews: processing expert insights, generating focused research questions, conducting a second round of web research, designing commentary points, outlining and writing the final article. The pipeline ends with the article and its metadata ready for editorial review and acceptance.

**Prerequisite**: Group 00 (`agents/00.orchestrator.md`) must have completed before this group runs. The materials library (`materials/`), initial research excerpts (`01.research/`), and summary (`02.summary/`) must already exist.

## Input Sources

When running inside the dsh plugin workspace, inputs are files under `input/` at the project root:

- `input/news-lead.md` — the news lead. **Read it** and use as `{NEWS_LEAD}`.
- `input/expert/*.raw.md` — expert interview transcripts (one per expert), each formatted as:
  ```
  Name: <expert name>
  Role: <expert role/affiliation>

  <raw interview transcript or notes>
  ```
- `input/expert/skip.json` — present when the editor chose to skip experts (contains `{}`).

When a parameter is supplied directly (e.g. `{EXPERT_INPUTS}`) with no corresponding file, use the parameter as before; the file form takes precedence. The project root is your working directory; all paths below are relative to it.

## Prerequisites

Before starting, read and understand:

1. `references/methodology/research-overview.md` — understand the research angles and overall goals
2. `02.summary/initial-summary.md` — understand the current state of research
3. `run.json` — check which stages are already done; resume from the frontier, never rerun completed stages

## Execution Flow

### Stage Three: Expert Interview Processing (Human Input)

**Goal**: Process expert interview transcripts into structured insights.

**Precondition**: Group 00 completed; expert material provided (via `input/expert/`) or the editor chooses to skip.

**Execution Method**: First, ensure workspace directories exist:
```
03.expert-insights/
04.research-questions/
05.deep-research/
06.commentary-points/
07.outline/
08.article/
```

**If the editor skipped experts** (input/expert/skip.json present, or the user says "skip experts"): mark the `expert` stage skipped, leave `03.expert-insights/` empty, and proceed to Stage Four.

**Otherwise**: For each transcript file under `input/expert/`, launch an independent subagent:
> Please read `agents/11.expert-processor.md` and execute strictly according to that Blueprint.
>
> Parameters:
> - RUN_ID: {unit id}
> - EXPERT_NAME: {name from the file}
> - EXPERT_ROLE: {role from the file}
> - RAW_INPUT: {the transcript content}

If there are multiple experts, launch subagents in parallel (up to 7). Do not strip or paraphrase transcripts; keep expert voices intact.

**Completion Indicator**: `03.expert-insights/{expert}.md` files exist for each processed expert.

Record Stage Three completion time in `run-log.md`. **All timestamps in run-log.md and run.json must use ISO 8601 format with seconds precision: `YYYY-MM-DDTHH:MM:SS`.** Then aggregate `03.expert-insights/index.json` (see Stage Index Aggregation below).

>
> Parameters:

> - RUN_ID: {unit id}

### Stage Five: Deep Research (Fully Automated)

**Goal**: Conduct a second round of focused web research based on the generated research questions.

**Precondition**: Stage Four completed.

**Execution Method**: The question generator produces research questions organized into thematic groups. Launch independent researcher subagents for each group, in parallel (up to 7 simultaneous).

For each research question group, launch a subagent:
> Please read `agents/13.deep-researcher.md` and execute strictly according to that Blueprint.
>
> Parameters:
> - NEWS_LEAD: {the news lead}
> - RUN_ID: {unit id}
> - QUESTION_GROUP_NAME: {group name}
> - QUESTIONS: {the specific questions in this group}
> - GROUP_ID: {group identifier, e.g., "Q1", "Q2", ...}

**Completion Indicator**: `05.deep-research/` has subdirectories with `excerpts.md` for each question group. New materials (if any) are saved in `materials/`.

**Verification**: Check that at least half the question groups produced useful excerpts. Record any gaps in `run-log.md`. Then aggregate `05.deep-research/index.json` (see Stage Index Aggregation below).

Record Stage Five completion time in `run-log.md`.

## Run Manifest Maintenance (OBV-03)

Update `run.json` at the project root at every stage boundary. Always read-modify-write: write `run.json.tmp` then rename over `run.json`. Keep the fixed 9-stage table declared at run start (indexes 0..8, see `agents/00.orchestrator.md`). Group 10 transitions:

1. Entrance: stage `expert` → `active` (or `skipped` if experts are skipped).
2. Stage Three done: `expert` → `completed`.
3. Stage Four start/end: `questions` → `active` → `completed`.
4. Stage Five start/end: `deep-research` → `active` → `completed`.
5. Stage Six: `points` → `active` while the designer runs; when presented to the user → `gated`; on user approval → `completed` and proceed to Stage Seven; on redo → `active` again, then `gated`.
6. Stage Seven: `outline` → `active` → `gated` → `completed` (same gate semantics).
7. Stage Eight: `article` → `active` → `gated` (review). On accept → `completed` and run `status` → `completed`. On revision → `active` again and rewrite.

**On any redo of an upstream stage, set the downstream stages to `aborted`** (e.g. redoing points aborts `outline` and `article`) and note it in `run-log.md`, so the interface shows them as expired. Status values: `waiting | active | completed | failed | skipped | aborted | gated`.

## Stage Index Aggregation (OBV-01)

- **After Stage Three**: for each `03.expert-insights/{expert}.md`, write an entry into `03.expert-insights/index.json`:
  ```json
  [{"id":"<expert-slug>","title":"<expert name>","file":"<expert-slug>.md","producer":"11.expert-processor","created_at":"<ISO 8601>"}]
  ```
- **After Stage Five**: for each group directory `05.deep-research/{GROUP_ID}/` that contains `excerpts.md`, write an entry into `05.deep-research/index.json`:
  ```json
  [{"id":"Q1","title":"<question group name>","file":"Q1/excerpts.md","producer":"13.deep-researcher","created_at":"<ISO 8601>"}]
  ```

Always read-modify-write with tmp+rename. An empty array means waiting, never an error. Keep artifact listings in the indexes, not in `run.json`.

## Continuation Discipline

- **Confirmed artifacts are ground truth.** If an artifact exists and its `run.json` stage status is `completed` or `gated`, do NOT regenerate or rewrite it, even when downstream stages run. Human edits to artifact files are final until the user explicitly asks for a redo.
- **Resume, don't restart.** On entry (or after a dsh restart), read `run.json` and check which stages are already done, then continue from the frontier. Never rerun a completed stage. If `02.summary/initial-summary.md` is missing, report that Group 00 must run first.
- **Stay inside the project root.** All reads and writes are limited to this directory.

## Important: Agent Invocation Standards

When invoking other Agents, you must follow these standards:

1. **Do Not Summarize or Paraphrase Blueprint**
   - Let the invoked subagent read the complete Blueprint file itself
   - You only pass parameters, not Blueprint content

2. **Each Independent Task Launches Independent Subagent**
   - For Stage Five, each question group launches a separate subagent
   - Do not package multiple question groups into one subagent invocation

3. **Standard Invocation Method**
   When launching a subagent, use the following format:
   "Please read `agents/XX.xxx.md` and execute strictly according to that Blueprint, parameters:..."

4. **Verify Subagent Results**
   - After receiving results, verify against Blueprint completion criteria
   - Results that do not meet criteria must require rework
   - Cannot consider complete based solely on subagent's self-report

5. **Completion Criteria are Non-Negotiable**
   - Completion criteria in Blueprints are hard requirements
   - When encountering difficulties, consult the user; do not lower standards independently

## Exception Handling

- If a research question group fails in Stage Five, record it in `run-log.md` and continue with remaining groups
- If a stage's subagent fails entirely, inform the user and ask how to proceed
- If the user wants to skip a stage (e.g., skip experts), accommodate and continue
- If the user wants to go back to a previous stage, accommodate (e.g., "let me revise the commentary points"); abort downstream stages in `run.json` as described above
